FINHOLDRA BETA 10.1.0 — CLOUD MULTI-DISPOSITIVO
================================================

Questa versione usa Supabase Auth (link email) + Postgres con Row Level Security (RLS).
Il proprietario della app configura un progetto una sola volta. Gli utenti finali NON
inseriscono API key o client ID: accedono con la propria email.

1) Crea un progetto su https://supabase.com/dashboard (regione UE consigliata).
2) Apri SQL Editor, esegui integralmente il file SUPABASE-SETUP.sql in questo ZIP.
3) In Authentication > URL Configuration imposta:
   Site URL: https://beta--finholdra.netlify.app
   Redirect URLs: https://beta--finholdra.netlify.app/**
   Se usi un dominio definitivo, aggiungilo e aggiorna Site URL.
4) In Authentication > Providers > Email abilita l'accesso tramite email e la
   conferma dell'indirizzo. Per la produzione configura SMTP dedicato, limiti di invio,
   anti-abuso e policy privacy (il servizio email gratuito di test ha limiti).
5) Copia Project URL e la PUBLISHABLE KEY in supabase-config.js:
   window.FINHOLDRA_SUPABASE={url:'https://xxxxx.supabase.co',publishableKey:'sb_publishable_...'};
   Non inserire mai service_role, secret key, password o token nello ZIP web.
6) Pubblica l'intera cartella su Netlify Drop; non pubblicare SQL privato con privilegi
   di scrittura al DB (il file SQL è distribuito come guida, non viene eseguito dal web).
7) Su iPhone e PC: Impostazioni > Backup e sicurezza > Account e sincronizzazione,
   email > Accedi via email > clic sul link ricevuto. La sessione resta memorizzata.
   Se è già presente un backup remoto, usa Carica dal cloud per sostituire i dati
   locali dopo avere esportato un JSON. Se il profilo è vuoto, l'importazione è automatica.

FUNZIONAMENTO
- Il backup include posizioni, acquisti, preferenze e rilevazioni storiche del profilo.
- Il salvataggio automatico si attiva dopo il primo collegamento, ogni volta che
  avvengono modifiche ai dati. Viene applicato un breve ritardo per evitare richieste ripetute.
- Se due dispositivi aggiornano lo stesso backup, una revisione numerica blocca il
  salvataggio obsoleto. Non c'è fusione automatica di operazioni concorrenti.
- I dati restano anche in locale; puoi sempre esportare/importare un JSON.
- L'app non cifra il JSON prima di inviarlo al DB. Supabase applica TLS e controlli
  di accesso RLS; per un lancio pubblico serve un'adeguata informativa privacy,
  gestione delle richieste di cancellazione e controlli security/SMTP.
- Prima di distribuire a terzi verifica email, lettura/scrittura RLS, ripristino e
  concorrenza su due dispositivi con account di test distinti.

NOTA IMPORTANTE
Nessuno può configurare il progetto personale Supabase senza autorizzazione
nell'account del proprietario. Il codice è pronto per il servizio, ma la
sincronizzazione online non funziona finché non viene compilato supabase-config.js
ed eseguita la migrazione SQL.
